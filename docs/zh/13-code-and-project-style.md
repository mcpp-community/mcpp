# 13 —— 代码与工程风格

**读者:** 开始编写一个模块、一个库,或为已有的库编写封装,并要选择其组织方式的人。

**本章回答的那一个问题:** 模块取何种形态,头文件与宏放在何处,这些选择中哪些因 mcpp 的构建而成本
更低。

**不在这里:** mcpp 对构建做了什么,见 [26 —— 构建优化](26-build-optimizations.md);库的发布接口,见
[11 —— 发布一个库](11-publishing-a-library.md);不带源码地分发一个库,见
[12 —— 分发预编译库](12-binary-distribution.md)。

以下各条是 C++ 模块的通行做法。标有 **mcpp** 的一句说明 mcpp 的构建为它增加了什么;没有这一句,
做法本身仍然成立。

## 模块的形态

| 形态 | 用于 | 编辑一个函数体所编译的 |
|---|---|---|
| 单文件,函数体在 `module :private;` 之后 | 应用的模块,或以源码发布的库的模块 | 该文件的片段 |
| 接口文件(`.cppm`)与实现文件(`.cpp`,`module m;`) | 不带源码分发的库;一个文件容纳不下的模块 | 实现文件 |
| 带分区的接口(`m:part`) | 接口本身很大的模块 | 该分区及导入它的单元 |
| 单文件,函数体在接口中 | 只有模板与 `inline` 函数 | 每一个导入者 |

- 没有其他要求时,写带私有片段的单文件:只读一个文件,该行以下的编辑不达任何导入者。
  **mcpp:** 片段被构建为独立单元,因此这一点对每个编译器成立,包括不能按原样构建片段的 GCC
  ([26](26-build-optimizations.md))。
- 不发布源码时,分发接口文件与预编译库:接口是使用者编译的唯一源文件
  ([12](12-binary-distribution.md))。
- 函数体在接口中的单文件模块,每次编辑都编译其导入者。**mcpp:** 导入者很多时,构建说明一次。

## 接口的内容

| 在接口中 | 在 `module :private;` 之后,或在实现单元中 |
|---|---|
| 导出的声明 | 非 inline 函数的定义 |
| 模板与 `inline` / `constexpr` 函数,连同函数体 | 没有导入者提到的辅助函数 |
| 导入者需要完整定义的类型 | 以不完整类型导出的类型的定义 |

- 导出得尽量少:没有导出的名字不会被依赖。
- 片段读取的内容要对片段可见:片段之上、未命名命名空间中的辅助函数对接口是局部的。把它声明在
  模块中(不导出),定义在片段中。
  **mcpp:** 读取这种辅助函数的片段按原样构建,构建给出所在的行。

## 头文件

- 模块单元只在全局模块片段中包含头文件:

  ```cpp
  module;
  #include <sqlite3.h>          // 读取这个头文件的唯一位置
  export module store.db;
  ```

- 一个头文件库只封装一次,放在它自己的模块中,其余单元导入该模块。封装以 `export using` 导出
  名字,下游不再包含头文件:它的宏与解析成本止于封装。
- 一个库的封装是独立的包,版本随所封装的库(索引中的 `mcpplibs.mwrap.<库>`)。**mcpp:**
  `mcpp add` 像解析任何依赖一样解析它,它的构建参数随包传递。
- 模块单元中以 `import std;` 取代标准头文件。

## 宏

宏不越过模块边界:导入者看不到它。每一种用途都有能越过边界的写法。

| 宏的用途 | 写法 |
|---|---|
| 常量 | `export inline constexpr` |
| 函数式的表达式 | 函数模板,或 `constexpr` 函数 |
| 按平台或特性选择代码 | 对一个 `constexpr` 事实使用 `if constexpr` |
| 库的配置(`#define LIB_OPTION`) | 构建该库的包的一个参数,在其 `mcpp.toml` 中写一次 |

```cpp
export module net.io;
import std;

export inline constexpr bool has_epoll = /* 目标的一个事实 */ true;

export void poll_once() {
    if constexpr (has_epoll) { /* ... */ } else { /* ... */ }
}
```

两个分支都被解析,因此未被选中的代码仍须引用存在的名字;对某个目标无法写出的分支放在为该目标
选择的源文件中(`[target.'cfg(...)'.build] sources`,[04](04-mcpp-toml.md))。

必须存在的宏——给出所在行的断言、库自身的 API——留在头文件中,由使用它的单元在全局模块片段中
包含。

## 名字与目录

- 模块名以包的命名空间开头:包 `acme.net` 中的 `acme.net.io`。**mcpp:** 不表达任何含义的顶层名
  (`core`、`util`、`common`)在校验时被拒绝。
- 目录的一层对应模块名的一段:`src/net/io.cppm` 提供 `acme.net.io`。
- 测试指明所测的模块,并像使用者那样导入它([08](08-testing.md))。
