# SPEC-002:目标侧模型与能力声明

| 项 | 值 |
|---|---|
| 规范编号 | SPEC-002 |
| 标题 | 目标侧模型与能力声明(`mcpp:` 保留命名空间) |
| 状态 | 评审中 v1.3 |
| 最后修改 | 2026-10-26 |
| 对应实现 | mcpp >= 2026.8.24.2;§2.2 的对象形式与 §7 mcpp >= 2026.10.26.1 |
| 相关设计文档 | `.agents/docs/2026-08-24-target-side-design.md`、`.agents/docs/2026-10-23-target-base-and-execution-host-design.md`、`.agents/docs/2026-10-26-control-contract-runtime-and-ide-ecosystem-design.md` §6 |
| 使用文档 | [docs/22 - 目标侧](../zh/22-target-side.md) |

本规范定义一次构建的目标侧由哪些层构成、每一层可以由谁供给、
供给者与需求者如何声明,以及引擎据此执行的规则。

用语按 RFC 2119:**必须 / 禁止**(强制)、**应当**(强烈建议)、**可以**(可选)。

---

## 1. 层

### 1.1 层的闭集 已实现

一次构建的目标侧**必须**由且仅由以下五层构成:

| 层名 | 内容 |
|---|---|
| `compiler` | 执行编译的程序 |
| `compiler-runtime` | 编译器自身的运行时:builtins 与展开器 |
| `kernel-abi` | 平台接口或其等价物 |
| `c-abi` | C 库 |
| `c++-abi` | C++ 库及其 ABI 运行时 |

层名是编译进引擎的闭集。实现名**禁止**出现在引擎代码中。

### 1.2 可供给性 已实现

除 `compiler` 外的每一层**可以**由包供给。`compiler` **禁止**由包供给:
编译器是引擎安装并驱动的载荷,族与族之间的差异是引擎必须持有的事实。
包**可以**要求某个 `compiler`。

### 1.3 来源 已实现

每一层的来源**必须**是以下四者之一:

| 来源 | 报告用词 | 可知时刻 |
|---|---|---|
| 编译器载荷 | `payload` | 依赖解析之前 |
| 被点名、按内容识别的预制目录(目标基座,SPEC-006 §3.9) | `prebuilt` | 依赖解析之前 |
| 依赖图中的包 | `graph` | 依赖解析之后 |
| 无 | `—` | — |

目标侧**必须**在依赖解析完成之后解析,且**必须**只解析一次。

## 2. 声明

### 2.1 `provides` 语法 已实现

```
mcpp:<层名>[=<实现名>]
```

`<层名>` **必须**属于 §1.1 的闭集;不属于时的处置见 §5.1(根工程报错、依赖警告)。
不以 `mcpp:` 开头的条目属于特性系统,引擎**必须**原样透传。

省略 `=<实现名>` 时,该层的实现名取包名。

### 2.2 `requires` 语法 已实现

与 `provides` 同语法。语义为:被命名的层**必须**解析为被命名的实现,
否则引擎**必须**在编译开始之前拒绝该构建。

省略 `=<实现名>` 时,语义为该层**必须**有供给者。

`requires` 的条目**可以**是表 `{ layer = "mcpp:<层名>=<实现名>", visibility = "public" | "private" }`。
字符串等价于 `visibility = "public"`。`private` 声明该需求只对本包自己的代码成立、
不越过本包的边界(C++ 运行时孤岛,§7.2);它**只**允许用于 `c++-abi` 层,用于其他层时
清单**必须**以 `requires-private-layer` 报错 —— 一个映像中的第二个 C 库不是孤岛,而是两个 C 库。

`requires` **可以**写在 `[target.<选择器>]` 下。生效的需求是 `[package] requires` 与所有匹配
选择器的 `requires` 的并集,合并规则与 `requires_abi` 相同。

### 2.3 标准库模块源 已实现

供给 `c++-abi` 的包**可以**在 `[build]` 下声明:

| 键 | 类型 | 含义 |
|---|---|---|
| `std-module` | 路径 | `std` 模块源,相对包根 |
| `std-compat-module` | 路径 | `std.compat` 模块源 |
| `std-module-flags` | 字符串数组 | 编译该模块源所需的 flag |

三者的 `[package]` 写法**必须**继续被接受。`[build]` 写法**应当**优先,
因为只有它可以按 `[target.'cfg(...)'.build]` 条件化。

声明了 `std-module` 而没有相应 `provides` 条目的包,引擎**必须**报错。

**部分实现**:`std-module` 与 `std-compat-module` 是单一路径,不可条件化;
仅 `std-module-flags` 参与条件合并。

### 2.4 预制目录的声明 已实现

一个预制目录供给哪一层、实现与版本,**必须**由测量回答(SPEC-006 §3.9.3):
驱动预处理探针翻译单元得到 C 库的实现与版本。测量回答不了时,
`[target.<三元组>].sysroot = { path = "…", provides = ["mcpp:c-abi=<实现>"] }`
的 `provides` 作为声明;测量回答了时,`provides` 用于核对。
由包名点名的预制载荷,接口名仍取包名。

## 3. 规则

### 3.1 规则一:每层恰好一个供给者 已实现

同一层出现两个供给者时,引擎**必须**在解析期报错,
并**必须**同时指出两个包及各自进入依赖图的路径(直接依赖或传递依赖)。

同一个包在 `provides` 中为同一层给出多条条目时,视为一个供给者;
其中命名了实现名的一条**必须**优先。

目标基座是一个供给者:它供给 `c-abi` 时,依赖图中再有 `c-abi` 的供给者,**必须**按本规则报错。
一个目录作为 `--sysroot` 寻址,当且仅当它供给 `c-abi`(c-abi 独占律)。

### 3.2 规则二:为其下方的层配置过 部分实现

一个实现**必须**在它曾被配置的层之上使用。引擎**必须**执行:

- 编译器载荷的 `c++-abi`,仅在 `c-abi` 同样来自该载荷,或来自一个被测量为同一实现的目标基座时可用;
- 后一种情形下,编译器运行库所需的 C 库版本(其 version need 中最高的 `GLIBC_x.y`)**禁止**高于基座的版本,
  违反时**必须**在编译前拒绝并说出两个版本(可测量的下限);
- §2.2 声明的每一条 `requires`。

「`compiler-runtime` 必须与 `compiler` 同族」当前**依赖供给者自行声明
`requires`**,引擎不独立推断 —— 因为推断需要一张实现名到族的映射表,
而 §1.1 禁止引擎持有实现名。

### 3.3 规则三:跨来源接线 部分实现

两层来自同一来源时,引擎**禁止**介入它们之间的关系。
两层来自不同来源时,只有引擎同时知道两边的地址,因此**必须**由引擎接线。

当前实现覆盖「两层均来自图」与「两层均来自载荷」。
「一层预制、一层来自图」的接线尚不完整。

可叠加的层(内核头文件、第三方头文件与库)由引擎以 `-isystem` / `-L` 接线;本机的目标基座缺少
内核头文件时,引擎**必须**补上生态的内核头文件,而**禁止**写入基座。

`c-abi` 层来自图时,链接的库搜索同样属于图:引擎**禁止**让驱动器从宿主推导库目录,
这样的链接上每一个 `-L` **必须**位于工具链存储、构建目录或图中某个包之内;
`[build] allow_host_libs = true` 解除这一约束。由 clang 链接的 ELF 目标已实现
(mcpp 2026.9.26.1,链接带指向构建目录内空目录的 `--sysroot`,mcpp#696);经 MinGW
驱动器的 PE 链接尚未实现,待其从宿主 MinGW 解析的导入库清点完成。

### 3.4 规则四:三元组是请求 已实现

三元组的 env 段**必须**被当作对 `c-abi` 的请求,而非其答案。

- 段缺席 ⇒ 未作陈述,任何供给者都不与之矛盾;
- 段存在且与解析出的 `c-abi` 不同,且后者来自图 ⇒ 引擎**必须**报出该不一致,
  并**必须**给出不含该段的目标拼写;**禁止**据此使构建失败。

拒绝曾被实现并被实测否掉:它打破了每一个把宿主目标拼作 `x86_64-linux-gnu`
的工程与 CI 配置 —— 而那正是 `mcpp toolchain list` 打印的拼写。
判据是该请求**不改变任何东西**:图两种写法下都供给同一个 C 库,
因此该段是被忽略而非被违反。

规范化会把 `x86_64-linux` 写成 `x86_64-linux-gnu`,因为身份必须是全的。
请求**必须**在规范化之前捕获;报告**应当**显示工程书写的拼写。

### 3.5 目标表的约定何时生效 已实现

目标行的 `pin` 命名的是**供给该目标 C 库的载荷**,不是偏好的编译器。
它**必须**仅在两个条件同时成立时生效:清单对该目标未作陈述,
且依赖图中无人供给 `kernel-abi` 或 `c-abi`。

第二个条件在依赖解析之后才可知,因此工具链**必须**在其之后解析。
过早决定被双向实测否掉:无条件应用会替换用户用 `mcpp toolchain default`
设下的工具链;不应用会让一个零依赖的交叉构建从可用变为不可用。

## 4. 报告

### 4.1 默认输出 已实现

构建**必须**报告解析出的结果而非清单中的意图。
默认**应当**只列出来源不是编译器载荷的层;五层均来自载荷时**应当**只输出目标行。

`MCPP_VERBOSE=1` 时**必须**列出全部五层。

### 4.2 诊断 已实现

诊断**必须**列出该判断所依据的每一层,包含来源为编译器载荷的层。

### 4.3 标识 已实现

报告**应当**使用与 `[dependencies]` 中一致的包名拼写。
全限定名**应当**仅在以下三种情形出现:`MCPP_VERBOSE`、
同一次构建中两个短名相同、以及诊断信息。

## 5. 兼容性

### 5.1 未知名字 已实现

**谁的清单决定答案。**

- 出现在**根工程**清单中的未知层名,引擎**必须**报错。
  这是作者自己的拼写,而他正看着这次构建。
- 出现在**依赖**清单中的未知层名,引擎**禁止**据此使构建失败;
  **必须**警告并忽略该层。该清单是对着一个更新的引擎写的。

清单中其它位置的未知键,引擎**禁止**据此使整份清单加载失败;**应当**警告并忽略。

第二条来自一次实测。在其落地之前,一个声明了新层名的包
**在该层被命名之前发布的每一个引擎上都无法加载**,因此层名词表对已发布的包
永远不可扩展:

    error: dependency 'openkal-llvm-runtime': mcpp.toml: error:
           `provides = ["mcpp:compiler-runtime=compiler-rt"]` names no
           capability mcpp knows.

这条规定只在**未来**的引擎上生效。一个包若要声明某个层名,
其使用者的引擎仍须不早于该层名被引入的版本。

### 5.2 既有拼写 已实现

- 能力名 `hosted-standard-library` **必须**继续表示 `c++-abi` 层;
- 工具链族拼写 `openkal-llvm` **必须**继续解析,归一为 `llvm`;
- `[package]` 下的三个 `std-module*` 键**必须**继续被接受。

## 6. 目标侧执行 已实现

### 6.1 组合

一个产物**必须**按 `<run_under…> <runner…> <产物> <参数>` 执行。`runner` 说明用什么执行(模拟器、
运行器包),`run_under` 说明经过什么到达执行宿主(Bazel `--run_under` 的语义)。`run_under` 的值按
覆盖(`MCPP_TARGET_<三元组>_RUN_UNDER`,空值视为未设置,`none` 表示清除)、工程(`[target.<三元组>].run_under`)、
机器默认(`config.toml` 的 `[target.<三元组>].run_under`)取第一个;没有引擎默认。`--no-runner` 表示该三元组
在本机是原生的,`runner` 与 `run_under` 都**必须**去掉。两者的程序都**必须**先在声明的载荷 `bin/` 中查找,
再在 `PATH` 上查找。

### 6.2 运行器契约

经过 `runner` 或 `run_under` 执行时,引擎**必须**设置:

| 变量 | 含义 |
|---|---|
| `MCPP_RUN_TRIPLE` | 目标,mcpp 的规范拼写 |
| `MCPP_RUN_KIND` | `exe`;产物是目录时为 `bundle` |
| `MCPP_RUN_MODE` | `run` 或 `test` |
| `MCPP_RUN_ID` | 每次执行唯一;运行器可能被并发调用 |
| `MCPP_RUN_CLOSURE` | 运行闭包清单的路径:带 `schema` 版本的 JSON,含产物、它从自身目录加载或读取的文件、基座的根 |
| `MCPP_SYSROOT` | 被陈述的目标基座的根,没有时不设置 |
| `MCPP_RUNTIME_FILES` | 既有的文件清单(TSV),保留 |

运行器**可以**包装运行器,argv **必须**原样传递;运行器的退出码即程序的退出码。工具专属的变量
(例如 `QEMU_LD_PREFIX`)**禁止**由引擎设置,由对应运行器的包从 `MCPP_SYSROOT` 转换(SPEC-006 §3.11)。

### 6.3 物理边界

本机没有任何路径能执行的产物,**必须**在执行前被拒绝,并给出 `run_under` 的写法。当前的判据:
非 macOS 宿主上的 Apple 产物,且没有 `run_under`。`mcpp test` 把这种情形报告为未运行。

## 7. 一个进程一套 C++ 运行时 已实现

### 7.1 原理

两套 Itanium C++ ABI 运行时(libstdc++、libc++/libc++abi)共用同样的 ABI 符号名:`__cxa_*`、
`__gxx_personality_v0`、`std::exception` 一族的类型信息与虚表、`operator new/delete`。同一进程的
全局符号空间里,它们要么各用一半(mcpp#838:抛出用一边、捕获用另一边,带类型的 `catch` 失效),
要么互相串用。`std::runtime_error` 等类型在两边的内存布局不同。因此**不存在**让"多个映像 + 两套
运行时 + 异常跨映像"可靠的链接写法。

### 7.2 三种模式

| 模式 | 成立条件 | 引擎的义务 |
|---|---|---|
| **U 统一**(默认) | 一个进程只有一套 C++ 运行时,由 §3.1 的唯一供给者决定:编译器载荷、目标基座或依赖图 | `requires` 不满足时**必须**在编译前拒绝,并给出补救 |
| **I 孤岛** | 某个组件的 C++ 运行时只存在于它的 C 接口之后,且由包以 `visibility = "private"` 声明 | **必须**机械验证 §7.3 的全部条件,不满足即拒绝 |
| **H 宿主决定** | Python 扩展、JNI、宿主插件:`c++-abi` 由目标基座陈述 | 包服从基座 |

能统一就统一:依赖图的 `c++-abi` 恰为所需实现时,孤岛声明不生效。

### 7.3 孤岛的条件

1. **我们一侧只有一个 C++ 映像**:按根包声明的全部目标判定,没有含 C++ 的共享库目标。不满足时
   **必须**在规划期以 `[cxx-runtime-island]` 拒绝。自身运行时静态嵌入并隐藏。
2. **一套展开器**:`--unwindlib=libgcc`。
3. **链接顺序**:外来运行时由引擎放在自身运行时之后(链接行的 `foreignCxxRuntime` 位置),规则包
   **禁止**把它写进 `$ldflags` 之前的位置。
4. **布局相关的冲突集**:链进映像的孤岛目标文件(孤岛包的 role=Object 动作产出)**禁止**以未定义
   符号引用布局相关的冲突集(`std::exception` 一族中除 `std::exception` 自身外的构造、析构与 `what`)。
5. **ABI 层整体绑定到自身运行时**:链接后的映像**禁止**以 `GLIBCXX_*`、`CXXABI_*` 版本导入 ABI 层
   冲突集中的任何符号。
6. **不跨运行时按类型捕获**:映像引用或定义的 typeinfo,**禁止**同时由一个建立在外来运行时上的
   共享库导出。

条件 4–6 在链接后检查,违反时**必须**以 `[cxx-runtime-collision]` 拒绝并列出符号。

**各目标格式**:上述条件按 ELF 的全局符号作用域推导。PE 按导入表绑定:条件 1 放宽为"我们一侧的
所有映像共用同一个运行时映像",条件 3、5 照常成立。Apple 平台只有 libc++,MSVC ABI 只有一个运行时
家族,两者都不存在孤岛。

### 7.4 外来运行时的识别

外来运行时**必须**按类型识别,**禁止**在链接参数中搜索子串:

- 链接行上被点名的运行时库(`-l:libstdc++.so.6`、`-lstdc++` 等,按词读取);
- 链接输入中的共享库,其 `DT_NEEDED` 含外来运行时的 SONAME(`libstdc++.so.*`、`libc++.so.*`、
  `libc++abi.so.*`;只看直接输入,不递归)。

识别出、但没有任何包以 `private` 声明的外来运行时,按孤岛条件校验:全部满足时构建并警告
(兼容读法 `undeclared-cxx-runtime`,docs/51),不满足时拒绝。

### 7.5 依赖图供给的 libstdc++

`c++-abi` 来自依赖图中的 libstdc++ 供给包、而编译器为 clang 时,引擎**必须**:以 `-nostdinc++`
加供给包的头文件目录编译;以供给包的 `std-module` 预编译 `std`(源文件不是模块扩展名时以
`-x c++-module` 编译);链接带 `-stdlib=libstdc++`,运行库与展开器仍为 `--rtlib=compiler-rt
--unwindlib=libgcc`(`compiler-runtime` 层不变,§3.2);向构建程序暴露 `MCPP_CXX_STDLIB` 与
`MCPP_CXX_ABI_ROOT`。
