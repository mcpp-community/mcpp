| 项 | 值 |
|---|---|
| 规范编号 | SPEC-018 |
| 标题 | 一次编辑之后哪些单元重新编译:按 BMI 内容截断、`bmi_cutoff`、构建目录的记录 |
| 状态 | 评审中 v1.1 |
| 版本 | 1.1 |
| 最后修改 | 2026-11-26 |
| 对应实现 | mcpp >= 2026.11.17.2;§2.1 的时间戳在 UTC 下自 2026.8 起成立 |
| 相关设计文档 | `.agents/docs/2026-11-17-ninja-cascade-publish-supplement-design.md` §3 |

用语按 RFC 2119:**必须 / 禁止**为强制,**应当**为建议,**可以**为可选。

## 0. 这份规范存在的原因

ISO C++ 不定义 BMI,也不定义构建;一次编辑之后哪些单元重新编译,由编译器写入 BMI 的内容与
构建工具的截断方式共同决定。#946 在 4 个编译器、8 种源码布局、8 种编辑上测得约 300 个结果:
决定级联的只有一件事,即被导入的 BMI 的字节是否变化。本规范规定 mcpp 如何判定"变化"。

## 1. 截断

1. 一个单元的编译边**必须**只以它直接导入的 BMI 为隐式输入。
2. 模块接口的编译边**必须**保留此前的 BMI,编译,再比较新旧两个文件;按第 2 节判定为不必
   传播时,**必须**放回旧文件及其修改时间,使导入者保持最新。
3. mcpp **禁止**自行计算接口摘要:导入者能观察到的每一处变化都在 BMI 的字节中,比较的正确性
   由编译器保证。
   保留、比较与放回**必须**由编译边的执行器完成,不得写成生成命令中的 shell 片段:各宿主的
   行为相同。
4. C 与 C++ 的编译边**必须**保留此前的对象,编译,再比较新旧两个文件;字节相同时**必须**
   放回旧文件及其修改时间,使归档与链接它的边保持最新。对象没有读者,也不受 `bmi_cutoff`
   影响:一个字节不同即为不同。
5. 工作区成员、`path` 依赖与 `git` 依赖在使用者的构建图中编译,截断对它们与对同一包的单元
   相同;包不是编译边界。

## 2. 两个 BMI 的差别

比较的结果为三者之一:

| 结果 | 含义 | 导入者 |
|---|---|---|
| 相同 | 字节相同,或只在该格式的读者屏蔽的部分不同 | 不编译 |
| 仅位置 | 记录的源码位置移动,别无变化 | 由 `bmi_cutoff` 决定(第 3 节) |
| 变化 | 其余一切 | 编译 |

mcpp 不认识的格式按字节比较,结果只有"相同"与"变化"。

### 2.1 GCC(`.gcm`)

1. `buildtime:` 与 `localtime:` 两个时间戳**必须**被屏蔽。`localtime:` 带宿主的时区缩写,
   屏蔽到其终止符为止,不限于 `UTC`。一个 BMI 中的时间戳多于两个时,**必须**按字节比较。
2. "仅位置"的判定:两个文件大小相同、段表相同,且除以下部分之外字节相同——时间戳、
   `.gnu.c++.olm` 段(行映射)、`.gnu.c++.cfg` 段的第 0–3 与第 8–11 字节(该段与模块的
   校验和)。
3. 新旧 BMI 任一含有 `__builtin_LINE` 或 `__builtin_source_location` 时,**禁止**判定为
   "仅位置"。模板体内读取位置的调用在实例化处求值,取自行映射:实测在
   `template<class T> constexpr unsigned f(T) { return __builtin_LINE(); }` 之前插入一行,变化
   的只有 `.olm` 与 `.cfg`,导入者得到的常量由 3 变为 4。`import std` 之下
   `std::source_location::current()` 在 BMI 中留下第二个名字。非模板的 inline 函数在解析处
   折叠,其所在段随之变化。
4. 构建图以 `-fcontracts` 编译时,**必须**按确切内容比较:合约的违例给出断言所在的行。

实测的范围(gcc 16.1.0):在 BMI 记录的全部位置之后插入一行,BMI 只有时间戳不同;在全部
声明之前,或前置声明之后的非 inline 函数体内插入,为"仅位置";在两个带函数体的声明之间
插入,其后各实体的段变化,为"变化"。

### 2.2 Clang(`.pcm`)

没有读者。BMI 不含时间戳;改变文件字节的编辑(包括注释)即改变 BMI,且没有可按段隔离位置的
结构。`bmi_cutoff` 对它无效。

2026-11-26 对 clang 20.1.7、22.1.8、23.1.3、23.1.6 的测量(SPEC-019 §8):非 inline 函数体不在
BMI 中,函数的 32 位 ODR 哈希仍在,并随函数体变化;该哈希在记录中的下标随声明的形式而不同
(同一版本的 `DECL_CXX_METHOD` 为 26、27、29),且随版本移动;哈希随机,约三分之一的编辑改变
其 VBR 宽度,使其后的位偏移与偏移表同时变化。可靠地屏蔽它们需要声明记录的布局模型,
没有这个模型不能保证不遮住接口的差异,因此 clang 的 BMI 仍按字节比较。

## 3. `bmi_cutoff`

| 取值 | "仅位置"的 BMI |
|---|---|
| `"ignore-locations"`(默认) | 保留旧 BMI,导入者不编译 |
| `"exact"` | 替换,导入者编译 |

1. 取值按层次:`MCPP_BMI_CUTOFF`(一次运行)、`[profile.<name>] bmi_cutoff`、引擎的默认值。
   其他取值**必须**被拒绝。
2. 保留旧 BMI 时,导入者中来自该模块的行号是此前的行号:诊断、调试信息(含内联与模板代码的
   行表)、覆盖率与 sanitizer 的报告。程序的行为不受影响(§2.1 第 3、4 条)。
3. `mcpp pack` 在 profile 带调试信息时**必须**使用 `exact`。
4. 取值为 `exact` 的一次运行**必须**先移除此前保留的每个 BMI,使其编译边运行、导入者随之
   编译;此后的产物与从空目录构建的相同。

## 4. 构建目录的记录

构建目录中有四个文件,截断的每一处比较都在该目录中进行:

| 文件 | 内容 |
|---|---|
| `bmi-cutoff` | 本目录的取值(`ignore-locations` 或 `exact`) |
| `bmi-changes.tsv` | 本次运行中不"相同"的每个 BMI 一行:`<bmi>\t<changed\|locations>\t<kept\|replaced>` |
| `bmi-kept.list` | 当前以此前的行号保留着的 BMI |
| `objects-same.list` | 本次运行中编译为原有字节的对象 |

1. 一次运行结束时,mcpp **必须**以一行说明被替换的 BMI(其导入者已编译),以另一行说明被
   保留的 BMI(其导入者未编译,给出此前的行号),并写出使其编译的取值。
2. 没有 BMI 变化时**禁止**输出这两行。
3. 编译为原有字节的对象的个数只在 `--verbose` 的输出中给出。

## 5. 实现的位置

截断与目录的记录属于 `mcpp.buildopt.keep`(`modules/buildopt`),不认识任何编译器;一种 BMI
格式的读者是它旁边的一个模块(`mcpp.buildopt.keep.gcm`)。新增一种格式的读者,即新增一个
模块与 `difference` 中的一行。保留、比较与放回由编译边的执行器完成(`mcpp.build.schedule`),
执行器只调用 `mcpp.buildopt.keep`,不含任何格式的知识。本规范的各项判定在 SPEC-019 的登记表
中各有一个条目;`MCPP_BUILDOPT=off` 时不保留任何产物。

## 6. 不在本规范之内

- 编译器把导入者的 BMI 绑定到被导入的 BMI(GCC 的 CRC,Clang 的贡献 BMI 哈希)所致的传播
  (#946 O3、O4):属于编译器。
- 索引包升级时依赖它的缓存包按 Merkle 键重建(O8):保守是设计。
- 拆分代码生成的调度(`bmi_schedule = "on"`,GCC)中由监督进程写出的对象不比较。
