## 0. 这份规范存在的原因

标准构建指:每个单元一条编译边,编译器写出的每个输出原样保留,输出之后的每一步都执行。mcpp
在此之外做的事——保留字节未变的产物、屏蔽 BMI 中的时间戳、改变模块边的形态、把一个源文件
构建为多个单元——此前分散在生成器、执行器与各自的规范中,其中一项写成 POSIX shell 片段,
在没有该 shell 的宿主上不存在。本规范把它们列在一张表中,规定每一项的级别、默认值与开关,
并规定通用管线与它们之间的边界。

## 1. 登记表

1. mcpp 在标准构建之外所做的每一项**必须**是登记表(`mcpp.buildopt.registry`)的一个条目;
   表外**禁止**有这样的行为。
2. 条目**必须**说明:标识、作用的接缝、级别、默认是否开启、改变它的清单键与环境变量。默认开启而有清单键的条目**必须**另说明
   `check`:只关闭这一项以做验证的取值(§9);编译器之间不同时,另说明 GCC 上的取值。
3. 包的 README **必须**以表格列出全部条目及其默认值与参数;测试保证二者一致。

| 条目 | 接缝 | 级别 | 默认 | 参数 | 作用 |
|---|---|---|---|---|---|
| `keep-bmi` | 边 | 严格 | 开 | — | BMI 编译为原有字节时保留,导入者不编译(SPEC-018) |
| `keep-object` | 边 | 严格 | 开 | — | 对象编译为原有字节时保留,不归档、不链接(SPEC-018 §1) |
| `gcm-stamps` | 边 | 严格 | 开 | — | GCC BMI 的两个时间戳不算差别(SPEC-018 §2.1) |
| `gcm-locations` | 边 | 有条件 | 开 | `[profile.<name>] bmi_cutoff`,`MCPP_BMI_CUTOFF` | GCC BMI 只有行映射移动时保留(SPEC-018 §3) |
| `scan-pass` | 图 | 严格 | 开 | — | 图的扫描先于编译,作为单独的一遍执行 |
| `split-schedule` | 图 | 形态 | 关 | `[build] bmi_schedule`,`MCPP_BMI_SCHEDULE` | BMI 存在时导入者即开始,不等编译器退出(SPEC-011) |
| `private-fragment` | 源码 | 源码 | 开 | `[build] private_fragment`(`unit`、`conservative`、`as-written`),`MCPP_PRIVATE_FRAGMENT` | 私有模块片段构建为独立单元(§5) |

## 2. 级别

| 级别 | 含义 | 默认 |
|---|---|---|
| 严格 | 产物与标准构建逐字节相同 | 开;没有自己的参数 |
| 有条件 | 程序相同,程序之外的信息可以不同(导入者给出的行号) | 在条目规定的守卫之下开;有参数 |
| 形态 | 图或进程的形态不同;产物相同,失败的方式是新的 | 在每个宿主上运行过之前关;有参数 |
| 源码 | 一个源文件构建为与其写法不同的单元 | 有参数;条目对没有把握的源文件按原样构建时开 |

1. 级别决定默认值:低风险且收益经过测量的条目默认开启,其余由参数开启。
2. 条目的级别提升**必须**有测量,并在每个宿主的 CI 上运行过。

## 3. 接缝

通用管线在三处询问 `mcpp.buildopt`,不认识任何条目:

| 接缝 | 位置 | 询问 |
|---|---|---|
| 源码 | 扫描之后、校验之前 | 一个源文件构建为哪些单元 |
| 图 | 计划写成图时 | 模块边取何种形态 |
| 边 | 每条编译边的执行器 | 此前的 BMI 或对象是否保留 |

1. 保留、比较与放回文件的执行器,以及写图的生成器,属于管线;判定属于 `mcpp.buildopt`。
2. 一种编译器的专门知识**必须**是所属部分之下的独立模块(`mcpp.buildopt.keep.gcm`);
   新增一种编译器不改动通用部分。
3. 全部条目关闭时,管线的结果**必须**是标准构建。

## 4. 总开关

1. `MCPP_BUILDOPT=off` 对一次调用关闭全部条目:不保留任何产物,不改变边的形态,源文件按
   原样构建。
2. 该调用**必须**先移除此前以较早行号保留的 BMI(SPEC-018 §3 第 4 条),其后的产物与从空
   目录的标准构建相同。
3. 严格级别的条目只受总开关控制。

## 5. 私有模块片段作为独立单元

```cpp
export module m;                     export module m;          // 接口单元
export int f();              →       export int f();
module :private;
int f() { return 1; }        →       module m;                 // 实现单元
                                     int f() { return 1; }
```

片段中的内容按语言规则不可为导入者所达([module.private.frag]);编译器并不据此构建。
实测(2026-11-17,模块 `c` 被 `b` 导入、`b` 被 `main` 导入,编辑片段内一个函数体):

| 编译器 | 按原样构建 | 构建为两个单元 |
|---|---|---|
| clang 23.1.3 | `c`、`b`、`main` 均编译:BMI 随源文件的任何字节变化(精简 BMI 为默认,仍有 153 字节不同) | 只编译实现单元 |
| gcc 16.1.0 | 不能构建:`module :private;` 未实现 | 只编译实现单元 |

1. `private_fragment = "unit"`(默认)时,含私有片段的主接口单元**必须**构建为两个单元:
   片段之前的文本为接口单元;全局模块片段的原文、`module <名>;` 与片段的文本为实现单元。
2. 两个单元**必须**以 `#line` 指回原文件及其行号;诊断、调试信息与 `__FILE__` 给出原文件。
3. 生成的文件只在文本变化时写入;原文件所在目录**必须**保持在两个单元的包含路径中。
   编译数据库除两个单元之外**必须**有原文件的一项(接口单元的命令作用于原文件),供语言服务器
   查询;按改动选择测试时,原文件的改动等同于由它构建的单元的改动。
4. 下列情况**必须**按原样构建,并说明所在行与原因:
   - 片段之前、模块范围之内有改变片段含义的预处理指令:`#define`、`#undef`、`#include`、
     `#pragma`、`#line`,以及下面没有列出的指令,或 `_Pragma`、`__pragma`(宏与编译状态不随 BMI
     进入实现单元)。条件指令(`#if`、`#ifdef`、`#ifndef`、`#elif`、`#elifdef`、`#elifndef`、
     `#else`、`#endif`)与 `#error`、`#warning` 不在此列:条件只决定哪些声明存在,实现单元
     经 BMI 取得声明;
   - 在 `export module` 声明所在行或片段所在行,条件指令尚未闭合(两个单元不会闭合它);
   - 片段之前有未命名的命名空间,或命名空间作用域的 `static`(`extern "C" { … }` 与
     `extern "C++" { … }` 是命名空间作用域);
   - 片段之前有命名空间作用域的 using 指令;
   - 自模块声明至片段之间有行连接(行末的 `\`);
   - 该单元是分区,或片段之前读不到 `export module` 声明。

   编译器不支持按原样构建私有片段时,该说明为警告;否则只在 `--verbose` 中给出。
5. 判定只读文本,不做语义分析;没有把握时按原样构建。通过上述判定而仍不能作为独立单元
   编译的片段,其错误由编译器给出并指向原文件;`private_fragment = "as-written"` 按原样构建。
6. 取值按层次:`MCPP_PRIVATE_FRAGMENT`、`[build] private_fragment`、默认值。其他取值
   **必须**给出警告并取默认值。
7. 取值 `conservative` 仍把片段构建为独立单元,而第 4 条的预处理指令一项回到放宽之前的规则:
   片段之前的模块范围内出现任何预处理指令即按原样构建。它是只退回这一处放宽的办法,在不能
   按原样构建片段的编译器(GCC)上,`as-written` 不是可用的验证办法时由它代替。
8. 判定读文本的记号而不是行:注释与字符串、字符、原始字符串字面量的内容不是代码;数字分隔符
   (`1'000`)属于数字,不是字符字面量的开始;原始字符串可以跨行并含任何文本。第 4 条的
   词法修正不设开关:它只使更多的源文件按原样构建。

## 6. 构建后的建议

建议不是登记表的条目:它不改变构建,只读构建已有的数据(本次被替换的 BMI、计划中的导入关系)。

1. 一次构建中,重编译的起点是一个只有一个文件的模块(没有实现单元,没有分区,没有被构建为
   独立单元的私有片段),且导入它的单元(直接或经由其他模块)不少于 5 个时,构建**必须**
   以一行说明:模块、文件、单元数,以及把函数体放到 `module :private;` 之后即成为独立单元。
2. 同一模块在同一构建目录中**必须**只说明一次(`buildopt-advice.list`)。

## 7. 语义提供者

源码接缝的条目以文本给出单元,管线写入并扫描,不关心来源。需要语义分析的条目由语义提供者
(如语言服务器)经该接缝提供;提供者是与 mcpp 并列的工具,经包生态安装,不是本包的一部分。

1. 提供者不可用、超时或给不出有把握的结果时,源文件**必须**按原样构建。
2. 提供者**禁止**在构建中调用 mcpp;编译参数由 mcpp 给出。
3. 无标记拆分对提供者的要求:每个定义是否 inline、模板、constexpr 或推导返回类型;函数体的
   范围;函数体引用的、对接口的翻译单元局部的实体。

## 8. 已记录、未实现

| 项 | 预期收益 | 未实现的原因 |
|---|---|---|
| 无标记地把单文件模块拆为接口与实现 | 编辑函数体不达导入者,无需写 `module :private;` | 需要语义分析(§7 第 3 条);gcc 上编辑函数体本不级联,收益主要在 clang |
| clang:导入者可观察的接口不变时保留 BMI | clang 上函数体与注释的编辑止于该模块 | 2026-11-26 的实测(clang 20.1.7 至 23.1.6):非 inline 函数的哈希在记录中的下标随声明而不同(同一版本的成员函数在 26、27、29),需要复刻序列化器的布局;32 位哈希随机,约三分之一的编辑改变其 VBR 宽度,之后的位偏移与三类偏移表(声明上下文的词法偏移、`TYPE_OFFSET`、`DECL_OFFSET`)随之移动;不屏蔽哈希则只覆盖最后一个声明之后的编辑。没有误屏蔽接口差异的保证,不实现 |
| 按符号计算受一次改动影响的测试 | `mcpp test --since` 运行更少的测试 | 需要跨导入的引用;动态分派可能遗漏测试 |
| 同一程序中一个库的两个版本各自改名 | 依赖链指定两个版本时可以构建 | 只对纯模块的包可行;头文件、C 库与宏不能改名;出现的频率没有测量 |

## 9. 失败时的提示

默认开启的条目在绝大多数工程上正确;少数工程遇到预料之外的失败时,构建**必须**说明怎样只关闭
这一项来判断它是不是原因,且**禁止**在与它无关的失败与成功的构建上说。

1. 提示以 `tip:` 行给出,在命令的输出之后,不改变退出状态,`--quiet` 下不给出(`diag::on_failure`)。
2. 提示从失败的**步骤**出发,不从"这次构建用过哪些条目"出发:

   | 规则 | 失败的步骤 | 强度 |
   |---|---|---|
   | R1 | 源文件是私有片段拆出的单元 | 点名原文件 |
   | R2 | 编译一个单元,它导入了当前以此前的行号保留着的 BMI | 点名模块 |
   | R3 | 链接,而图中有拆出的片段或保留着的 BMI | 说明无法归属到单元 |
   | R4 | 其他任何步骤 | 不给出 |

3. 失败的步骤取自 ninja 的 `FAILED:` 行与步骤记录;取不到时按 R4。测试程序的运行失败不给出提示。
4. 文本由登记表行的清单键、环境变量与 `check` 组成:`MCPP_PRIVATE_FRAGMENT=as-written mcpp build`
   (GCC 上为 `conservative`)、`MCPP_BMI_CUTOFF=exact mcpp build`;并写出 `MCPP_BUILDOPT=off`
   是下一级。两步之后失败依旧,原因不在这些条目之中。
5. 构建图与此前的取值不同时,第一次构建**必须**按新的取值重新生成图:`MCPP_BUILDOPT`、
   `MCPP_PRIVATE_FRAGMENT`、`MCPP_BMI_SCHEDULE` 的陈述是图自身所记的请求(`build.ninja` 首行的
   `request=`)的一部分,快速路径在重放之前比较它。这一陈述**禁止**只记在构建的记录里:记录由成功的
   构建写下,而用来核对的陈述正是给失败的构建用的。核对的那一次构建无论成功还是失败,其后不带陈述、
   没有编辑的构建**必须**与核对之前的那一次相同。
6. 提示所读的计划数据写在构建目录的 `buildopt-applied.tsv`,快速路径(没有计划)读同一个文件。
