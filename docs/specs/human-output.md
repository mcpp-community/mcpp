## 0. 范围

本规范约束面向人的输出的**形态**:哪一条流、什么介质、哪几种行、何时有颜色。它不约束
逐字内容;面向人的输出没有兼容承诺,程序读取的是
[docs/50](../zh/50-machine-output.md) 的信封与记录。agent 与 CI 读到的是管道中的输出,
因此管道中的形态与终端中的形态同等重要。

## 1. 两条流 已实现

标准输出携带命令的**结果**(程序的输出、文档、列表、`mcpp test` 的报告);标准错误携带
**叙述**(状态行、进度、`warning:`、`error:`、`note:`、`tip:`、编译器诊断)。划分规则与
例外见 docs/50 §3。`--quiet` 去掉叙述,保留警告、错误与诊断。

## 2. 两种介质 已实现

1. **终端介质**:标准错误是能移动光标的终端时,构建在输出下方保留一行状态行,只有这一行
   被原地重绘;已经写出的行**禁止**被改写、重新着色或移动。
2. **日志介质**:管道、文件、`TERM=dumb`、不支持虚拟终端序列的控制台。**禁止**写出任何
   光标移动或回车重绘序列;行在内容确定后写出一次。构建静默 60 s 后追加一行心跳
   (`Building <完成>/<总数> · <时钟>`),之后每 60 s 至多一行。

## 3. 行的种类 已实现

| 种类 | 形式 | 用途 |
|---|---|---|
| 状态行 | 右对齐到第 12 列的一个词,后接主体:`   Compiling app v0.1.0 (.)` | 命令正在做或已经做完的事 |
| 消息行 | `error: …`、`warning: …`、`note: …`、`tip: …` | mcpp 自己的判断 |
| 续行 | 缩进到消息正文的列 | 消息的细节、列表 |
| 补救行 | `help: …` | 读者下一步可以执行的命令或要改的键 |
| 诊断 | 编译器、链接器的原文 | 内容本身 |

1. 状态行的词:进行中的工作用现在分词(`Resolving`、`Compiling`、`Running`、`Waiting`、
   `Packing`、`Installing`),完成的工作用过去分词(`Finished`、`Packed`、`Installed`),
   报告的事实用名词标签(`Home`、`Default`)。构建的主线固定为
   `Resolving` → `Compiling` → `Finished`,`run` 另有 `Running`。
2. 一条错误存在可执行的下一步时,**必须**以一行 `help:` 给出;下一步是一条命令时,写出
   完整的命令。外部工具(xlings)给出的补救按原样转述。
3. 带位置的消息**必须**以 `<path>:<line>:<col>: ` 或 `<path>: ` 开头,与编译器诊断同形,
   编辑器与终端可以直接跳转;信封中的诊断由此得到 `path` 与 `range`(docs/50 §2)。
4. 编译器诊断**必须**原样完整输出,mcpp **禁止**截断或改写;mcpp 自己的列表**应当**
   有上限,并说明省略了多少(`… and N more`)。

## 4. 颜色 已实现

优先级从高到低:

1. `MCPP_NO_COLOR=1` 或非空的 `NO_COLOR`:关闭。
2. `CLICOLOR_FORCE` 非空且不为 `0`,或 `FORCE_COLOR` 非空且不为 `0`、`false`:开启,
   管道同样开启。状态行仍只在终端介质中绘制。
3. 否则:终端开启,管道关闭。

颜色只修饰状态行的词、消息行的前缀与强调,**禁止**承载其他地方没有的信息。
